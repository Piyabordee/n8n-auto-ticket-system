# Data Model

> Database schema for the Auto Ticket System — ticket and log tables in Microsoft SQL Server.

---

## Overview

The system uses two tables in SQL Server: `[YourDatabase].[dbo].[ticket]` for ticket lifecycle data and `[YourDatabase].[dbo].[log]` for audit trail entries. All mutations are logged through the LogSQLServer sub-workflow.

---

## Context Snapshot

- **Database**: `[YourDatabase]` on Microsoft SQL Server (sanitized name)
- **Two tables**: `ticket` (primary data) and `log` (audit trail)
- **Primary key**: `message_id` (LINE message ID) — unique per LINE message
- **Timezone**: Timestamps stored in UTC; n8n adds +7 hours for Asia/Bangkok display

## Table: ticket

The primary table storing ticket lifecycle data. Each row represents one LINE message that was classified as a ticket.

| Column | Type | Description |
|--------|------|-------------|
| `message_id` | VARCHAR | **PK** — LINE message ID |
| `status` | VARCHAR | Current status: `pending`, `assigned`, `closed`, `Unclose`, `unsent` |
| `assigned_to` | VARCHAR | IT staff display name (set on assignment) |
| `assigned_date` | DATETIME | Timestamp when ticket was assigned |
| `intent` | VARCHAR | AI-classified intent: `INC` (Incident) or `SR` (Service Request) |
| `category` | VARCHAR | Main category (Software, Hardware, Network, Camera, Printer, Requested) |
| `sub_category` | VARCHAR | AI-classified sub-category |
| `branch_name` | VARCHAR | Branch name from AI extraction |
| `branch_company` | VARCHAR | Company or Franchise designation |
| `subject` | VARCHAR | Email subject line (generated by AI summary) |
| `clean_text` | NVARCHAR | Cleaned message text (emojis, @all removed) |
| `raw_text` | NVARCHAR | Original raw message text |
| `email_body` | NVARCHAR | Full email content sent to helpdesk |
| `chatname` | VARCHAR | LINE group/room display name |
| `fromuser` | VARCHAR | Sender display name |
| `userid` | VARCHAR | LINE user ID |
| `groupid` | VARCHAR | LINE group ID |
| `created_date` | DATETIME | Ticket creation timestamp |
| `updated_date` | DATETIME | Last update timestamp |
| `created_by` | VARCHAR | Creator (system or user) |
| `updated_by` | VARCHAR | Last updater |
| `close_cause` | NVARCHAR | Problem symptom (extracted from IT reply) |
| `close_reason` | NVARCHAR | Resolution description (extracted from IT reply) |
| `close_time_minute` | INT | Minutes from assignment to closure (computed via DATEDIFF) |

## Table: log

Centralized audit log capturing all ticket operations. Populated by LogSQLServer sub-workflow.

| Column | Type | Description |
|--------|------|-------------|
| `table_name` | VARCHAR | Table where action occurred (e.g., `[YourDatabase].[dbo].[ticket]`) |
| `table_row_id` | VARCHAR | Affected row ID |
| `action_type` | VARCHAR | Action: `INSERT`, `UPDATE`, `UNSEND`, `CLOSE`, `UNCLOSE` |
| `value` | NVARCHAR | Human-readable description of the change |
| `created_date` | DATETIME | Log entry timestamp |
| `created_by` | VARCHAR | User or system that performed the action |
| `message_id` | VARCHAR | Related ticket message ID |

## Key Relationships

```
ticket.message_id ←──→ log.message_id
```

- Every ticket mutation (INSERT, UPDATE, UNSEND, CLOSE) generates a corresponding log entry
- The log table does not enforce FK — it's append-only audit data
- `close_time_minute` is computed at close time: `DATEDIFF(minute, assigned_date, GETDATE())`

## Close Data Extraction

When closing a ticket, cause and reason are extracted from the IT staff's reply text:

```
close_cause:   (?:อาการ|ปัญหาอาการ)[\s=:]*([\s\S]*?)(?=\s*การแก้ไขปัญหา)
close_reason:  การแก้ไขปัญหา[\s=:]*([\s\S]*?)(?=\s*@|$)
close_time:    DATEDIFF(minute, assigned_date, GETDATE())
```
